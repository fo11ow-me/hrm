## 需求
- 遵循系统化调试原则:"NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST"
- 在执行优化前,必须先诊断当前系统状态
- 避免基于假设进行优化,必须基于数据驱动的决策
- 多角色辩论提供了优化方向,但缺少当前状态的诊断数据

### 性能诊断发现 (2026-06-08)

**中等风险问题 (P1 - 尽快配置/优化)**:
1. **数据库连接池参数缺失** - HikariCP未配置最大连接数等关键参数
   - 代码位置: application.yml:8-20
   - 影响: 生产环境可能出现连接池耗尽
   - 修复: 添加maximum-pool-size、minimum-idle等配置

2. **前端打包优化缺失** - 未配置代码分割、Element UI/ECharts未按需引入
   - 代码位置: vue.config.js
   - 影响: 首屏加载时间长(~2.5MB未压缩)
   - 修复: 配置splitChunks、按需引入组件

3. **缓存策略缺失** - JWT验证和权限数据未缓存
   - 影响: 高并发时CPU开销大,数据库查询频繁
   - 修复: 实现短期缓存策略(30秒JWT验证缓存)

4. **JVM参数未配置** - 生产环境缺少堆内存和GC配置
   - 影响: 性能不稳定,可能OOM
   - 修复: 配置-Xms、-Xmx、G1GC参数

**性能实现良好的部分**:
- ✅ EasyExcel流式解析替代Hutool DOM模式
- ✅ HikariCP高性能连接池
- ✅ Redis Lettuce异步客户端配置合理
- ✅ SSE连接超时和异常处理完善
- ✅ 文件大小限制合理(20MB)

**高风险问题 (P0 - 立即修复)**:
1. **CORS配置过于宽松** - 允许所有来源(`*`)访问API,存在CSRF和数据泄露风险
   - 代码位置: SecurityConfig.java:53
   - 影响: 任意域名可发起跨域请求
   - 修复: 限制为受信任的域名列表

**中等风险问题 (P1 - 尽快修复)**:
1. **文件上传缺少类型验证** - 仅通过扩展名判断,未验证文件内容
   - 代码位置: DocsService.java:71
   - 影响: 可上传恶意文件
   - 修复: 添加文件类型白名单和Magic Number验证

2. **Cookie缺少Secure标志** - 未强制HTTPS传输
   - 代码位置: LoginController.java:93-97
   - 影响: 中间人攻击风险
   - 修复: 生产环境设置 `setSecure(true)`

3. **JWT解析失败处理不足** - 失败时仅记录警告,未明确拒绝
   - 代码位置: JwtAuthenticationFilter.java:79
   - 影响: 可能导致未认证请求通过
   - 修复: 增强异常处理

**安全实现良好的部分**:
- ✅ JWT双令牌策略 (Access 15分钟, Refresh 7天)
- ✅ BCrypt密码加密
- ✅ 文件上传路径遍历防护
- ✅ 环境变量管理敏感信息
- ✅ 细粒度权限控制 (@PreAuthorize)

## 技术决策

| 决策 | 理由 |
|------|------|
| 诊断优先于优化 | 系统化调试原则:没有根本原因调查就不应该修复。辩论提供了优化方向但缺少当前状态数据。 |
| 分层诊断策略 | 安全、性能、架构、前端四个维度独立诊断,避免单一视角的盲点。 |
| 数据驱动决策 | 所有优化建议必须有量化数据支持,避免基于直觉或最佳实践的盲目优化。 |
